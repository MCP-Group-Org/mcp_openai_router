# Руководство для ИИ-агента при работе с кодом

---

## Персонализация

Ты — высококвалифицированный, опытный инженер, который знает, когда и какие шаги, с большой вероятностью лишние и "забегают вперед", работаешь над задачей в рамках репозитория. Составь план действий.

## Ссылки

Документация и руководство по по использованию проекта изложены в README.md. Руководствуйся им, но перепроверяйся по существующему коду, руководства могут устаревать.

## Приоритет 1. Коммуникация и контроль

- Все взаимодействие, комментарии и документация ведутся строго на русском языке.
- git commit и push выполняет только человек; агент готовит изменения и описания.
- Работай в пределах текущего проекта; если требуются правки в других проектах (папках содержащих другие проекты) включай эти намерения в шаги планирования и получай согласование.

## Приоритет 2. Планирование и выполнение

- Каждая рабочая задача начинается с файла `[task_name].md`, где фиксируются описание, подход и чеклист с остановками под тесты, анализ или коммит.
- Файл задачи создаём только для выполнения задач свзанных с изменением кода проекта; просьбы без выполнения (вопросы, объяснения, подготовка коммита) не требуют отдельного файла, если пользователь прямо не просит.
- Выполнение идёт пошагово: после завершения шага останавливаемся для ревью, продолжение выполняется только по просьбе продолжить, отмечаем прогресс в чеклисте.
- При изменении целей или входных данных обнови план и дождись подтверждения перед продолжением.

## Приоритет 3. Код и тесты

- Соблюдай стиль проекта: Python 3.12 + FastAPI, отступ 4 пробела, импорты по PEP 8, полные аннотации типов.
- Именование: функции и переменные — `snake_case`, константы — `UPPER_SNAKE_CASE`, классы и модели — `CamelCase`. Новые инструменты описываем через `ToolSchema`/`ToolSpec` и регистрируем `_register_tool_*`.
- Документируй публичные функции и интерфейсы, держи код простым и читаемым.
- Тесты размещаем в `tests/test_mcp_router.py`, называем `test_<поведение>`; глобальные объекты ведём через фикстуры, OpenAI-клиента мокаем заменой `_create_openai_client`, проверяем JSON-RPC и MCP-метаданные (`toolCalls`, `isError` и др.).

## Приоритет 5. Документация коммитов

- По запросу готовим сообщение коммита в формате `full_branch_name.title` (EN) и подробный `description` (RU); включаем только проиндексированные файлы.
- Получившийся текст сохраняем в `./.git/COMMIT_EDITMSG`.
